# 中国法定节假日自动更新

在“设置 → 事件 → 节假日与节气”控制。默认启用，可随时手动检查。这里更新的是放假与调休上班安排，不是 Sparkle 软件更新；无需发布新应用版本即可取得新年度数据。

## 数据源

客户端按顺序尝试以下三个不同服务，一个源返回完整有效数据后停止该年份的后续请求。所有请求均为 HTTPS，不请求 GitHub、GitHub Pages 或 raw.githubusercontent.com。

| 顺序 | 服务 | 年度地址 | 数据格式 |
| --- | --- | --- | --- |
| 主源 | [holiday-calendar · Gitee](https://gitee.com/cg-zhou/holiday-calendar) | `https://gitee.com/cg-zhou/holiday-calendar/raw/main/data/CN/{year}.json` | `year / region / dates`，区分 `public_holiday` 和 `transfer_workday` |
| 备用 1 | [提莫](https://timor.tech/api/holiday) | `https://timor.tech/api/holiday/year/{year}/` | `code=0 / holiday`，`holiday` 布尔值区分休／班 |
| 备用 2 | [程序世界](https://appworlds.cn/holiday/) | `https://date.appworlds.cn/year/{year}` | `code=200 / data`，包含放假和补班，不包含普通周末 |

接入时已实测三个服务的 2026 年数据：均包含 33 个放假日、6 个补班日，日期和休／班属性一致。未来年份需等待国务院发布安排及服务维护者更新，不能根据农历猜测调休。主备机制处理服务不可用、超时、限流和响应异常，不承诺第三方服务永久可用；也不对三源做投票，主源返回有效数据时以主源为准，内容可能存在维护延迟。最终请以国务院公告为准。

## 白天调度与补查

- 采用本机时区和公历，正常每天 10:00 检查当前年和下一年。使用一次性计时器，不按秒或分钟轮询，也不创建系统唤醒任务。
- 首次运行无成功记录，或之前整天漏检时，在 08:00–22:00 启动、唤醒或恢复活动后补查。当天只是还没到 10:00 时继续等待 10:00。夜间启动先等到白天；夜间手动检查允许执行。
- 检查成功以“当年下载数据有效且已持久化”为准，同一本机自然日不再自动检查。下一年尚未公布或获取失败均保留旧数据，下一天继续检查，不把未来年份缺失当作当年更新失败。
- 当年更新失败时，30 分钟后重试；自动检查每天最多 3 次。重试跨过 22:00 时顺延次日 10:00。手动按钮可在失败后立即再试；手动成功也计入当天成功记录。
- 尝试次数、最近尝试／成功时间写入 UserDefaults，重启不会重置限流。自动检查关闭后停止计时，取消正在执行的自动请求，手动入口仍可用。还原显示设置会恢复默认开启。
- 唤醒、时区和系统时钟变化时重新计算下一次执行时间；应用关闭期间不会检查，也不会为了网络请求唤醒睡眠中的电脑。

## 缓存与资源

- 每次只请求当年和下一年；失败才访问备用源，不逐日请求。每次请求超时 8 秒，单请求资源超时 12 秒；关闭等待网络连接，避免离线挂起。连续年份之间间隔至少 1 秒，兼容备用接口限流。
- 使用临时 URLSession，无 Cookie、无磁盘 HTTP 缓存；响应上限 128 KiB。不上传事件、日历名称或用户资料。
- 校验年度、有效日期、重复日期、休／班类型、非空名称、合理数量及元旦／劳动节／国庆节三个日期。过少、空、错误年份、HTML 登录页等均不替换本地安排。允许下一年度文件带上前一年 12 月的跨年安排。
- 原子写入 App Group 的 `Library/Application Support/CalDock/holidays-v1.json`，写入成功才改变内存数据；更新某年不会删除其他年份。未变更的数据不重复写盘或刷新小组件。
- 主程序启动加载缓存；小组件只读取共享文件，不独立联网。更新后刷新已展开月历、重载 WidgetKit 时间线，并在通知启用时重排提醒。缓存不存在或损坏则回退内置 2026 年数据，损坏不会使月历空白。
- 缓存读取上限 2 MiB，已安装年份会保留以支持离线回看。主程序和扩展共享同一个受 App Group 授权保护的文件。

## 开发与验收

`Tests/CalendarCoreTests/Fixtures/` 保存接入时获取的三个真实年度响应，仅供离线回归，不会作为运行时数据源打包到应用。Gitee 数据的 MIT 许可保存在 `Sources/CalendarCore/Resources/HolidayData-LICENSE.txt`，主程序和小组件发布包均保留该声明。

```sh
swift test
# 可选：以原生 URLSession 实测三个国内源及生产抓取器
CALDOCK_LIVE_HOLIDAYS=1 swift test --filter HolidayUpdateTests/testLiveDomesticSourcesWhenExplicitlyEnabled
```

离线回归覆盖主源超时／格式错误后的连续切换、首次成功后停止请求、空数据与网络失败区别、无 GitHub 地址、缓存重启恢复、原子写入失败、旧日期移除、跨年覆盖、白天调度、漏检补查、一天一次、重试上限以及旧版偏好迁移。
